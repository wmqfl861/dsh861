# B02：桌面团队、Agent 与流程控制台

类型：产品开发任务入口。日期：2026-09-20。源码基线：`59579599fa34b6fff47b1c4d525459d2148eb1f8`。状态：主会话产品方案与任务包已编写，尚未实施；不是指定 Codex 的运行产物。

所有者本次明确要求：“桌面端功能太少了，我需要在桌面端能组团队，能操作别的agent，能设置工作流和循环。”本包据此把交付重心从 B01 的底座与可运行预览，改为可直接使用的桌面操作闭环。不得把再次打包、增加测试数量、修完旧CI或画出不能执行的页面当作本阶段交付。

## 必须可以直接操作的四件事

1. 在桌面创建团队、设置成员岗位和可用的执行配置、建立任务依赖并派给成员。
2. 在桌面查看和控制受管 Agent：启动任务、发送后续指令、停止当前执行、查看日志、错误、产物和能力限制。
3. 不手写脚本即可新建、编辑、保存、复制、运行有顺序/并行/条件/审核节点的工作流，运行中看到真实状态。
4. 设置固定次数、审核返工和按间隔重复的有界循环，能暂停、取消、限制调用及确认恢复；不能出现界面停止、后台继续无限派工。

实际已配置且授权的产品才可执行。内部子代理、受管外部 CLI、UI 演示 fixture 三者必须区分；缺少一个外部产品的条件不应阻止团队页面和流程核心开发，但不能把未接入产品标为可用。

## 分批交付，不再等所有后端写完才看界面

- V1：能从真正的桌面界面创建团队、添加成员、派一个任务并控制一个真实受管执行，重开后看到实际记录。
- V2：同一桌面能配置并运行完整流程，包括并行、条件、独立审核与有界返工。
- V3：间隔调度、崩溃后保守恢复、权限拒绝、调用上限和整体验收，形成新的 Windows 可运行产物。

以上是同一批次内的可运行切片，不要求所有者逐小任务发提示词。若某必需产品验收缺凭据/机器/制度放行，则报告准确的受影响项并继续独立任务，最后交部分结果而不是假完成。
