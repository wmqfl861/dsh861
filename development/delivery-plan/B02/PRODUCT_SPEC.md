# 桌面产品行为规格

类型：目标规格，尚未实现。所有“必须”均是B02验收目标，不是对当前产品的描述。

## 1. 一套入口，四个主要页面

桌面左侧提供“团队”“Agent”“工作流”“运行中心”四个常驻入口，当前项目/工作目录始终可见。原聊天、会话、文件与审批功能继续存在，详细执行从新控制台跳转原真实会话；不能把新入口藏在只有模型先调用工具才出现的卡片中。Web复用组件，但最终验收在实际Windows产物里完成。

界面默认中文，遵守项目locale机制；按钮权限、不可用原因、保存中/失败/冲突、没有配置、没有权限均有明确状态。所有动作由Host确认后更新真实状态，不用乐观动画证明任务已开始。

## 2. 团队页

### 用户操作

新建团队定义 → 选项目与根会话/新建根会话 → 添加成员 → 选角色和已批准执行配置 → 保存模板 → 启动团队 → 建任务/依赖 → 指派和观察。提供“开发者＋测试者＋审核者”模板和从空白开始，两者字段全部可编辑；角色不是永久绑定某一家模型。

成员编辑字段包括显示名、稳定成员ID、职责、harness/profile引用、模型配置引用、工具/权限预设、上下文fresh/fork、可写范围和并发策略。只选择已有获准profile，不在表单中显示/记录Key，不将工作流JSON当任意命令执行配置。运行中修改定义产生新版本，已运行实例保持原快照。

任务板列包括待执行、执行中、等待审核/人工决定、失败、已完成；显示负责人、依赖、运行ID、产物和错误。拖动并非直接修改状态：发CAS命令、Host检查权限和依赖；冲突提示重读，不覆盖别人的最新值。

### 现有Team约束必须可见

现有TeamId依附根Session，不允许UI自造另一个TeamId却未创建后端实体。成员名字不可重用；重命名显示字段与更换底层成员是不同动作。删除成员定义不等于杀死活跃进程，实际运行成员采用停用/归档，保留历史。

已有writeScopes是提示，不是沙箱。共享工作区下默认只允许一个写入执行，审核者只读；若要两个写者同时运行，必须证明独立工作区及合并策略，不以“两个输入框不同”假装隔离。首版可以并行运行只读审核和不冲突的安全操作，但不能承诺不存在的跨进程Team一致性。

## 3. Agent页

展示每个受管执行配置的产品名、程序版本、可用模型、能力、认证状态（不含秘密）、运行状态、最近错误。Codex、Claude Code、OpenCode、Grok保留四种产品目标；真实能力缺失显示不可用原因，不填一个同名空适配器。

操作包括启动一个任务、打开成员会话、发送后续指令、停止当前轮、停止整个指定run、重试已明确失败节点、查看结构化审核结果/日志/产物/用量。`暂停调度`与`停止当前模型请求`分开；one-shot不支持续接时禁用该按钮并说明，不能悄悄开新会话冒充继续。

只控制由本产品在明确项目/Session下创建并拥有的Agent或有既有授权连接的远端实例。禁止扫描并接管用户桌面上任意Claude/Codex终端、杀名字相同的进程或复制其他产品的全局凭据。

界面区分：可用、未配置、缺认证、能力不支持、运行中、取消中、已停止、需核实。选择模型时冻结到本次执行配置，不改全局默认或绕过已批准路由。用量未知显示未知；估算费用和已确认计费分开。

## 4. 工作流页

提供图形编辑区与结构化节点表，两种视图使用同一份定义。能新增/删除/重排节点、连线、编辑输入引用、绑定成员、检查图、保存新版本、复制和运行。不能把Mermaid图片或静态SVG加几个按钮当成可编辑执行器；也不要求用户编写JavaScript。

首批节点：Agent任务、已授权工具/测试动作、条件分支、并行分叉与汇合、独立审核、人工确认、有限循环、结束。等待间隔是循环/调度字段而非睡眠中的阻塞UI。每条边写清成功/失败/拒绝/条件，汇合默认等待全部必需前置；一个节点不能同时属于多个矛盾分支。

创建的流程在运行前校验：无悬空ID、无无界回边、节点类型和版本受支持、输出引用存在、条件类型正确、角色能力可满足、并发/预算合法。错误定位到具体节点和字段。导入导出仅传定义及版本，不带密钥、机器私有绝对路径、运行句柄或个人会话内容。

工作流例子：需求整理 → 开发 → 并行（测试、只读代码检查）→ 独立审核 → PASS结束 / FAIL进入有界返工 → 再次验证。模型写“PASS”文本本身不能完成审核节点；需要明确结构化结果和所审候选/产物身份。

## 5. 三类循环

| 模式 | 界面字段 | 停止与错误 |
|---|---|---|
| 固定次数 | 次数、循环体、每轮输入来源、是否保留会话、调用上限 | 0/负值/非整数拒绝；N轮完成后不再启动第N+1轮 |
| 审核返工 | 审核者、通过条件、最大轮数、失败反馈映射、每轮时间/调用上限 | 不通过才返工；达到上限显示耗尽，不伪记成功；空结果/非法审核输出进入错误或待人验 |
| 按间隔重复 | 间隔、时区展示、开始/结束、最多次数、重叠策略、离线错过策略 | 默认不重叠、不积压追跑；停止后不再调度；关机不会假装仍运行 |

三类必须结构化表示，不允许用户输入任意while(true)/eval条件。条件表达式用受限字段比较和布尔组合，长度/深度/输出大小有界。所有循环至少设置有限轮数或结束时间，同时有整个run的最大新调用次数与截止时间；用户显式设置后保存为版本化定义。默认值由正式计划确定并作为可见配置，不把本文示例数字变成隐藏协议常量。

模板示例可默认最多3轮、并发2；这些是待确认的产品默认建议，不是用户允许无限费用的授权。若模型不提供可靠token/费用上报，仍能按调用次数和时间硬停止，但费用字段标未知，不能宣称精确金额封顶。

## 6. 运行中心

显示流程版本、团队快照、成员与harness、节点时间线、当前轮数/上限、调用数/额度、产物与审核、下一次运行时刻和最后错误。每个状态能追到Host事件与实际Session，UI刷新、滚动或组件卸载不得改变执行。

“暂停”停止派发新节点，已发工作按明确策略完成到安全边界后显示已暂停；“取消”关闭新派发入口并请求取消该run自己的所有子任务，未确认退出前显示取消中。不能仅清一个前端定时器就宣告停止。

应用退出前提供停止并退出/继续保持应用运行等真实可支持动作。本阶段不安装系统常驻服务；应用完全退出或机器关机后不会继续跑。重启加载持久状态并标需核实/可恢复，不盲目重新发出状态未知的外部动作。恢复只继续已明确未执行的节点或按原产品能力重连，不伪称恢复任意JavaScript堆栈。

## 7. 最小用户验收旅程

在实际win-unpacked里从空白创建团队，配置开发/测试/审核三岗位，保存并重开；从图形或节点表创建流程；启动两条独立任务并观察真实各自输出；执行一次审核失败后的返工再审核；主动触发循环上限、暂停和取消；关闭重开看到同一run与产物，任何不确定动作保持待核实；没有所选产品配置时得到准确拒绝且调用计数不增长。

至少展示一个真实受管执行路径；跨harness验收需实际不同产品与对应授权。keyless集成可以真实执行Host调度与本地fixture，但不得把fixture输出标为真实模型结果。只完成页面、不接Host，或只完成引擎、没有桌面动作，都不能给B02功能完成。
