# B02 可操作功能验收

类型：验收参考。以下24项用于本阶段，不取代原AC-01—32。没有执行的格子标NOT_RUN/缺件；不得为获得PASS把必需功能改成仅文档设计。

| ID | 必需行为 | 可核对证据 |
|---|---|---|
| A01 | 常驻团队/Agent/工作流/运行中心入口，真实Desktop可进入 | 产品模式UI操作及路由/组合测试，不是隐藏fixture页 |
| A02 | 从空白创建团队定义、保存、关闭重开 | Host持久写确认、新根/Team关联及读回，不能localStorage自证 |
| A03 | 添加/配置成员、角色与能力受限profile；实际组队 | 后端成员ID与UI对应，未支持配置明确拒绝 |
| A04 | 任务依赖、指派、CAS冲突与历史归档 | 两客户端过期更新拒绝，依赖未满足不执行 |
| A05 | 指定成员启动、后续指令、当前轮Stop、跳转原会话 | 实际Session/handle关联，不通过名字匹配控制其他进程 |
| A06 | 未配置/认证/能力不支持显示准确且无暗中fallback | 拒绝前后外部调用计数、无秘密日志 |
| A07 | 图与节点表均可创建编辑流程，不要求手写JS | 添加/连线/重排/参数/保存/读回同一定义 |
| A08 | 定义版本固定、复制/导入/导出安全 | 旧run不受新模板影响，导出不含凭据/活跃句柄 |
| A09 | 顺序、并行及join执行真实节点 | 顺序依赖、双分支实际输出、失败分支不漏清理 |
| A10 | 类型化条件、独立审核与人工决定 | 非法输出/错误artifact hash/过期批准拒绝；不以PASS字符串冒充 |
| A11 | 固定N次循环严格有界 | N轮与调用日志一致，禁止N+1的负控有效 |
| A12 | 审核失败进入返工，通过退出，上限耗尽明确 | 实际FAIL→修改→再审，不同产物revision和review绑定 |
| A13 | 按间隔重复有下一时刻/次数/停止且不重叠 | 虚拟时钟机制测试＋真实Host持久恢复，重复tick不重启 |
| A14 | 调用/并发/时间限额在Host准入生效 | 同时争最后额度，禁止额外调用；费用未知不显示0或假封顶 |
| A15 | 暂停/取消的真实状态与资源关闭 | 不再派新工作、只取消本run、自有handles全部确认或明确仍待收敛 |
| A16 | 关闭重开恢复持久状态，未知副作用不盲重试 | 注入崩溃前后收据缺失，需核实状态与安全继续 |
| A17 | 存储失败、损坏/未知版本不假成功 | flush错误、CAS、部分日志和模板冲突拒绝 |
| A18 | 跨项目/团队/子树权限与写入范围真实有效 | 对其他项目操作拒绝；共享写冲突不被advisory字段假装隔离 |
| A19 | 运行中心实时状态、轮次、错误、人工节点与重连 | Host事件对应；重连去重，不触发额外run |
| A20 | 产物、日志、模型身份和用量可追溯 | run/attempt/Session/candidate/hash一致，未知和估算分列 |
| A21 | 三条用户旅程在新Windows可运行产物重放 | J1/J2/J3逐动作证据、产物hash、非开发服务器替代 |
| A22 | 至少一个真实受管执行；跨harness以实际不同产品证明 | 原授权下真实provider/程序/配置身份；两个不同产品才能声称跨harness通过 |
| A23 | B01已通过的必要桌面/退出/快照行为不回归 | 受影响非回归集，不要求无理由重复所有历史矩阵 |
| A24 | 最终完整候选指定硬审、正常hooks与准确报告 | actual model/variant、真实exit、明确裁决、candidate和交付一致 |

A01—A21属于桌面功能与工程完整性；A22是实际产品可用性，不能由keyless fixture替代。没有其所需授权时允许交FEATURE_PARTIAL，必须清楚说明用户目前哪些真实Agent不能执行。A23/A24不能省略。原四harness首版要求不因本阶段只验证两个而被删除。

## J1：从桌面组队和直接控制

在新的测试项目，从空白团队添加开发者与审核者，分别绑定已登记的可用执行配置和权限。保存并重开；创建有依赖的任务，指派成员；开始任务、观察真实输出、发后续指令、停止选中成员，确认另一个独立run仍存活。所有点击通过实际页面与Remote，不直接在测试里篡改UI store。

## J2：可编辑流程与审核返工

从图/表编辑器创建：开发 → 并行测试/只读检查 → 独立审核 → PASS结束或FAIL返工。第一次提供会失败的受控输入，真实测试失败后进入返工，修正产物后再次审核并完成；保存的定义版本、各轮产物hash和独立审核Session都可查看。负控伪造审核hash不得走成功边。

## J3：循环、限额、停止与恢复

分别执行固定次数和间隔重复；用显式限额限制新调用。流程进行时暂停，确认不新增调度；继续后取消，确认只停止本run。关闭Host后重开读取同一run，已完成动作不重做，未知动作进入需核实。关闭应用期间明确无常驻执行保证，不伪造错过周期的执行记录。

## 验证入口由实际新模块确定

先对新schema/Host/runtime的直接spec与边界reject运行，再执行renderer交互、真实组合、既有expected/Session及两SDK相关快照，最后在产物模式Electron走J1—J3。路径及原Vitest项目由C00根据真正文件登记；未创建路径不通过零发现冒充成功。

全覆盖率与跨平台矩阵仍由原CI，必要时新增直接运行不会隐式放开全仓refresh/record。新模型可见行为的预期来自真实执行并受独立审查；不能手工删工具、事件、错误或pending状态让golden变绿。

## 证据来源和审计

每项结果标明来自单元、替身、实际Host、实际Desktop、真实外部产品或固定CI；这些层次不可替换。图像须来自实际窗口，禁止用生成图片当程序截图。每次物理run记录实际command/工具/exit、输入candidate、产物hash和清理结果；同一日志拷贝不算两次运行。

独立复核除了读代码，还必须验证UI可达、关键按钮确实调用Host、权限由执行端检查、循环上限不能只在浏览器实现。完整产品尚缺数据平台或四产品接入时，不被“24项表格已填满”掩盖。
