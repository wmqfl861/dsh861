# 中断恢复入口

类型：恢复步骤。任务执行可能跨多个本地会话；不能依赖隐藏上下文，也不能声称没有进程仍在后台自动继续。

## 1. 停止前必须留下的记录

在当前 `development/delivery-runs/B01/<run-id>/` 保存：实际baseline、正在使用的计划版本/输入hash、任务状态、文件所有权、当前candidate、已运行命令/exit、正在等待的自有进程或Promise、尚未结束的push、有效授权来源及剩余阻断。未保存的退出码写MISSING，不在恢复时补造。

保留源码和所有未跟踪新增产物；不以清理工作区作为交接步骤。日志只保存必要安全内容，不复制全环境、HOME或凭据。

## 2. 新总控恢复顺序

1. 从本包入口和最近的执行状态读取已做工作，而不是重新从W00全量运行。
2. 核对branch、HEAD、远端ref、已声明本地原件、全部candidate路径和hash。发现不同先解释来源；不得reset/rebase/stash/clean让它看起来一致。
3. 只核对记录中的项目自有任务是否仍活跃，不能扫描/杀死任意用户进程。已有push未结束就不再发起第二次。
4. 对未确定完成状态的外部动作先核实是否发生，不能因前会话没回执就重复执行安装、推送或发布。
5. 取得资源所有权后，继续最早ready任务；仅重验输入变化或证据缺失的检查。未变化的正式计划、审核和昂贵测试直接引用。
6. 恢复时的状态/时间另记，不改旧记录；若某个必要环境仍不可用，维持其blocked并继续独立工作。

## 3. 恢复短提示词

```text
继续 dsh861 B01。先读取计划包README和最近delivery-runs/B01记录，
核对当前candidate、文件归属、活动任务与push，不重启仍在执行的工作。
按DEPENDENCIES选择ready任务继续，保留3个r44原件和已声明资料。
不重复已通过且输入未变的规划/测试，不覆盖历史证据。
只有整个阶段可交付或确实需要新的所有者决定时，才返回集中报告。
```

## 4. 计划变更

普通实现细节由总控在批准任务内处理；实际接口、验收条件或任务依赖需要改变时，由指定规划者作短版本化补充并说明影响。后继规划不覆盖原v1，也不将最初缺失的记录改成后来已经存在。范围外部分等待明确决定，其余独立任务继续。
