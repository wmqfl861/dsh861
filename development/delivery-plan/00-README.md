# dsh861 阶段式交付计划

类型：执行入口。版本：2026-09-19 / v1。源码基线：`7f63d03538759306f8363d5a912c1e99fbe015bf`。

本计划响应所有者的明确要求：把工作组织成可以连续执行的大阶段，由本地总控安排并行实施、阶段内独立检查和返工；主会话在阶段交付时集中验收，而不是每修一个小问题就转发提示词。本次交付的是完整产品蓝图和 **B01：可信基线与 Windows 桌面预览** 的具体任务包，不是声称完整软件公司已实现，也不是改变 P0 的正式验收状态。

## 开始顺序

1. 读 [基线](BASELINE.md)，确认当前分支及保留现场。
2. 读 [范围与权限](SCOPE_AND_AUTHORITY.md)，再读 [执行协议](EXECUTION_PROTOCOL.md)。
3. 读 [B01 阶段目标](PHASE_B01.md) 和 [具体任务卡](WORK_PACKAGES.md)。
4. 本地指定 Codex 对当前阶段形成正式执行计划和必要的精确文件登记；本包是主会话编写的规划输入，不能冒充该真实调用。
5. 按 [依赖清单](DEPENDENCIES.json) 分批派发；使用 [审核与测试](REVIEW_AND_TESTS.md)、[派发模板](DISPATCH_TEMPLATE.md) 和 [恢复入口](RESUME.md)。
6. 阶段结尾按照 [报告模板](REPORT_TEMPLATE.md) 交付一次汇总，主会话审核提交、CI 和实际产物。

直接给本地总控的指令在 [LOCAL_AGENT_PROMPT.md](LOCAL_AGENT_PROMPT.md)。状态种子在 [STATUS.json](STATUS.json)，首次执行复制为独立运行记录，不把模板中的 planned 改成已发生结果。

## 三个边界

- B01 是工程交付批次，不是新的 P0-C，也不把维护批次成功当作四种 harness 产品接入全部成功。正式节点仍以 [节点状态](../NODE_STATUS.md) 和绑定候选的真实审核为准。
- 工作量按完整工作包、依赖、联调和返工组织，支持连续多日执行；不以固定天数、修复轮数或测试条数承诺完工日期或产品百分比。
- 本计划单独存放于文档分支。未通过本地正常检查前，不自动把它合并到开发分支。读取计划不需要修改用户的工作树；正式纳入由唯一整合者按白名单完成。

## 本阶段应交给所有者的东西

至少形成可核验的 Linux 安全构建结果、稳定的关键快照验证、Windows 桌面预览产物或精确环境阻断、完整需求盘点、下一正式节点的准入清单和一份阶段交付报告。不得只回传大量 PASS 日志而没有用户可打开的产物或明确缺件说明。

不追求在本批次里顺手清理整个上游代码库。已知、与本阶段无关的覆盖率或平台问题保留在统一台账，不降低门槛，也不把它们每一项都拆成向用户索要提示词的小任务。
