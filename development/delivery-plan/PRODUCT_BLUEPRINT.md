# 多智能体软件公司产品蓝图

类型：规划参考。本文规定交付方向，不描述尚未实现的功能为现有能力。需求来源为 [主规格](../../MULTI_AGENT_REQUIREMENTS.md)、[开发路线](../../MULTI_AGENT_DEVELOPMENT_ROADMAP.md) 和 [节点规则](../../NODE_DEVELOPMENT_RULES.md)。本次不改三份权威文件、不缩减原首版要求。

## 1. 产品终点

所有者通过中文控制台创建软件项目，设置岗位、成员、规则、预算与执行配置，批准明确的操作范围。系统以独立工作区调度真实执行产品，完成需求、设计、美工、开发、测试和独立审核，保存可追溯产物，并在得到具体发布授权后交付网站、移动 App 和微信小程序。

首版不是多租户商业 SaaS，不包含公共 agent 市场，也不以更多 UI 面板代替真实执行。桌面壳复用已有 Electron/Web/Host，不重新开发一套平行后端。当前 Windows 主机可作为桌面与项目执行节点；平台 PostgreSQL/GBrain 的默认部署仍遵守规格中的 Linux 节点安排，不假定该 Windows 主机已有 Docker、WSL、数据库或 iOS 工具链。

## 2. 系统分层与权威数据

| 层 | 职责 | 数据与权限责任 |
|---|---|---|
| Web / Windows Desktop | 中文任务、项目、产物、规则与阻塞展示；提交命令而非直接改数据库 | Desktop profile 的可执行依赖和插件状态与 CLI 隔离；沿用现有进程/通信安全模型 |
| 公司控制服务 | 项目、岗位、成员、规则版本、审批、计划、调度、预算及审核状态 | PostgreSQL 是控制状态权威；任务必须持久化后才能确认接单 |
| 执行适配层 | Codex、Claude Code、OpenCode、Grok 的真实版本与能力适配 | 程序、配置、会话、技能与凭据访问范围隔离；不借全局安装冒充受管产品 |
| dsh 执行底座 | agent、工具、会话、取消、持久事件、SDK、插件与沙箱 | 保留已发布 Session 数据，不用平台数据库迁移覆盖原生记录 |
| 能力与知识 | 集中 tools/skills、授权访问、GBrain 长期知识 | 平台库与 GBrain 库使用独立逻辑库/账号；GBrain 不是审批与调度的唯一事实源 |
| 产物与交付 | Git、文件/对象、预览、构建、签名、发布记录 | 产物绑定任务、作者、候选版本和证据；签名/外部发布另行授权 |

禁止产生双重权威：浏览器不能自封任务验收通过；agent 最终文本不能直接充当审批状态；GBrain 不能替代事务状态；Git 提交存在不能替代运行证据。

## 3. 跨模块接口先定后并行

下表是后继正式设计需落实的职责，不是当前已存在的公共 API 名称。

| 接口责任 | 必须携带的信息 | 失败约定 |
|---|---|---|
| 任务接受 | project/member/task、固定 plan/rule/config 版本、授权引用、输入产物 | 数据库未确认写入，不返回已接单 |
| 执行请求 | attempt、harness 和程序身份、工作区、可用工具、预算、取消关联 | 无配置或权限时明确拒绝，不换模型或借全局凭据 |
| 执行事件 | 稳定事件/操作标识、关联 attempt、序列或来源证据、未知状态标记 | 收到消息、完成执行、验收通过分别记录 |
| 取消与恢复 | 被拥有的任务子树、已发请求与已确认停止、复原/交接依据 | 不杀其他任务；外部动作状态未知时不重复执行 |
| 审核决定 | 审核者真实身份、完整候选清单/哈希、需求映射、PASS/FAIL/BLOCKED | 候选变化使受影响审核失效；退出码零不等于 PASS |
| 知识访问 | 公司/项目/成员 source、授权、来源、纠正或失效关系 | 必需知识不可用则暂停相应步骤；其他独立任务可继续 |
| 交付索引 | 产物引用与哈希、预览/构建/安装/签名/发布各层状态 | 不以网页预览冒充真机、签名包或商店上线 |

公共类型、数据库迁移、共享规则和中央配置由一个责任者整合。消费者从冻结约定开发，不由并行 agent 各自猜测字段。版本冲突通过正式计划修订处理，不能把旧记录改写成符合新规则。

## 4. 全项目交付阶梯

| 批次/原阶段 | 可以展示给所有者的结果 | 可并行部分 | 串行前置与结束条件 |
|---|---|---|---|
| B01，当前维护批次 | Windows 预览、关键运行验证、真实问题台账、32项验收盘点 | Linux构建、Windows夹具、Desktop、文档、只读产品盘点 | 本包定义；不宣布P0-B通过 |
| M1a / P0-B | 四种真实harness隔离能力矩阵、允许/拒绝/取消/交接证据 | 各适配器在相同能力约定下互斥写入 | 指定计划/硬审与实际授权齐备；真实产品验收不能用开发CLI调用替代 |
| M1b / P0-C | 平台/GBrain独立账号与库、记忆合成数据读写/权限拒绝/失联恢复 | 数据部署、客户端契约、测试准备可按正式计划分工 | P0-B放行后才激活；没有数据库环境不能写成完成 |
| M1c / P1 | 在控制台创建项目、成员、授权与任务，持久派发、取消和产物记录可用 | 公共数据/状态契约冻结后，控制台、执行适配、工具权限、测试并行 | PostgreSQL事实确认、权限执行、版本关联及故障路径通过 |
| M2a / P2 | 一项真实小开发任务，从需求到实现、独立审核、预览与产物验收 | 产品/用例先行，工程与独立测试分开 | P1有效；不得等流程画布全部完成才运行第一个任务 |
| M2b / P3 | 集中技能/工具、跨harness记忆、可编辑依赖/返工/人工节点 | 记忆、能力服务、流程UI在共用身份上并行 | 持久任务模型稳定；四种harness仍是首版要求 |
| M2c / P4 | 同类预约业务的网站、Android/iOS、微信小程序，真实设计和素材 | 冻结设计/接口后各端独立实现与验证 | iOS/macOS与AppID条件独立登记；没有条件不冒充上线 |
| M3 / P5 | 组件版本共存、路由回退、迁移拒绝、数据库/产物备份恢复 | 独立故障场景与恢复验证 | 真实长任务及平台/知识数据已存在，升级不能杀旧实例 |
| 发布准备 / P6 | AC-01—32的证据包、运维/安装/升级文档、已知限制和发布候选 | 只读验收、说明与产物整理 | 所有必需项达标；外部发布、签名与采购仍需具体授权 |

后继行是架构与路线，不是让执行者在 P0-B 未通过时预先规划/实施 P0-C—P6 的命令。B01 结束可以集中提交一次准入报告；实际下一节点由规定的真实 Codex 在前置通过后制定。

## 5. 首个业务闭环

P2 的最小代表任务使用规格中的预约与服务管理业务的一项有限功能。完整路径是：输入需求和验收条件 → 持久任务 → 受控工作区 → 实际执行者修改 → 可重现测试 → 独立审核绑定候选 → 可查看预览/代码产物 → 用户验收。失败测试不能靠状态按钮盖过；若审核未过，流程进入返工，不标已交付。

B01 的 Desktop 预览只用于验证现成底座：启动、打开临时项目、执行标注为 keyless/replay 的测试任务、显示结果、取消、关闭重开及数据读取。它不是上述完整公司业务闭环，也不是四种付费模型产品验收。

## 6. 质量与进度

[需求矩阵](REQUIREMENTS_MATRIX.md) 采用未盘点、可复用代码、局部验证、产品验收通过、阻塞等状态。全部32项逐条保留，不能因为暂缺环境删掉某项。已批准历史节点仅证明当时的候选。

不以文件数、修复轮数、通过测试条数或9个里程碑等权比例报告整体完成率。进度汇报列出本次真正可打开的产物、通过的端到端场景、未完成必需项和新证据；没有估算依据时不给精确百分比。

## 7. 范围取舍

当前重点是可运行预览和可信执行，而不是再做一个漂亮但空的公司管理页面。底座问题按与本阶段交付的影响分级：安全/数据/权限及阻止必需流程的问题必须修；无关历史问题保留负责人、证据和后继范围，不降低阈值、不随意全仓清理。完整首版要求仍以原规格为准。
