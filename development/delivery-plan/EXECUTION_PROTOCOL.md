# 本地总控执行协议

类型：执行参考。负责者为一个持续维护任务图的总控实例。子代理不是独立拥有整个仓库的第二个总控。

## 1. 本地闭环

读取输入 → 确认范围/前置 → 派发互斥任务 → 实现者自检 → 全新上下文审核者检查固定文件 → 本地返工 → 总控整合 → 批次集成 → 规定的真实硬审 → 正常提交/必要CI → 阶段报告。普通返工在此循环内完成，不向主会话请求下一条微任务。

当前阶段的正式计划由真实Codex确认。本包已经给出目标、任务和测试要求，规划者只需进行当前源码核对、缺口补订和明确文件登记，不从零重复整个产品研究。正式硬审必须使用实际model/variant参数，模型自述不能代替调用证据。

## 2. 并发配额

初始开启2个实施子代理、1个独立审核者，总控不另占文件写入槽；在本机资源、已授权调用额度和文件互斥均允许时最多3个实施者。此为上限，不是必须凑满。重型build/打包/全量文档检查同时最多1个；轻型独立测试最多2个。浏览器、SDK服务器、临时home和端口均归任务独占。

只读盘点可与无关实现并行。审核某工作包时该包候选冻结，其他互斥包仍可继续；阶段最终候选审核期间所有写入冻结。整合、共享生成器、根build输出、Git和push由总控串行控制。

## 3. 文件与运行资源所有权

W00生成执行版FILE_OWNERSHIP表，每行含任务、完整路径、当前blob、读/写、产物目录及锁持有者。同一文件只有一个写者；W01与W02虽然原因不同，共享prepare spec，必须按依赖先后串行编辑，不能各写一版最后覆盖。

优先使用项目专用隔离工作副本和分支。不得把可写node_modules、lib输出或profile挂到多个并行构建中。现有依赖难以安全复用时，不擅自重装；改为同工作树的互斥文件实施，所有build/测试由总控持有资源锁执行。工作副本建立在既有获准临时根中，登记真实路径，不写其他项目。

全局环境仅用于已授权的工具启动；产品/测试环境使用显式白名单和独立home。Windows必须处理PATH/Path大小写与shell路径语义，不能把宿主命令偶然可见当作测试替身被执行。

## 4. 任务状态与继续条件

状态采用 `planned → ready → running → self_checked → review → changes_requested / accepted`。遇到外部条件是 `blocked_dependency`；需要新CI是 `wait_ci`；不在范围的是 `deferred`。`accepted`仅指该任务的验收，不能自动更改正式节点。

任务完成后总控根据DEPENDENCIES选择下一ready任务。一个包blocked时，只冻结依赖它的边，不冻结无关桌面、文档或只读盘点。没有可运行工作，或资源/调用额度不足以继续，才生成阶段中间恢复回执；不得声称无后台进程仍会自动工作。

同一失败最多连续尝试两次没有新证据的相同方法；之后必须换有明确因果依据的诊断方法。返工按原项目限制最多三轮后，若仍无进展进入总控根因检查或所有者决策，不靠无限重复换取一次绿。正常、有新证据的修复不因机械计数被隐藏为已通过。

## 5. 四级审核

- CP0：并行前检查范围、接口、依赖、资源和测试入口，由独立计划复核者检查，不修改实现。
- CP1：每个可整合工作包的固定候选，由非实现实例的新上下文审核；测试、错误和资源释放都必须查看。
- CP2：每波整合后检查组合行为、跨模块消费者、生成物和双语事实。关键接口、权限、持久化、取消或环境契约改变时立即触发，不等波末。
- CP3：阶段最终候选由规定的真实OpenCode做完整硬审，输入包括所有新增未跟踪文件。主会话之后做远端提交/CI/产物复核，不取代本机硬审。

实现者可以自检，不能自己写一份“独立PASS”。工具不可用不冒名，审核失败由本地总控安排返工。纯未变字节无需为Git提交身份重复全矩阵；受影响字节一变，必须按影响重验和重审。

## 6. 检查与证据预算

小改动先跑最小直接回归，再跑受影响组合和必要文档检查。共享host/client build产物按源码tree与工具版本建立复用记录，输入未变就引用已有证据，不每个子代理各跑一次完整build。

全coverage和跨平台穷举由既有CI执行；不在Windows默认运行整个矩阵。完整阶段最终检查仍必须覆盖所有必需交付，不能将“增量”当作跳过没有任何证据的路径。

每次物理运行一份原始日志和一行索引：command、cwd、工具版本、开始/结束、exit、文件/测试计数、输入candidate、输出hash、截断情况。manifest不记录自己以免循环。脱敏/规范化副本有明确名称和双hash，不覆盖首次失败，不复制同一运行充多次。

证据进入 `development/delivery-runs/B01/<run-id>/`（本地首次执行新建）。大安装包只记录本地路径/hash与既有授权产物托管位置；不把二进制、HOME、全配置和全环境塞入Git。没有远端产物渠道时如实交本地路径，不编造下载URL。

## 7. Git检查点

检查点按完整变更族，不按每个测试一提交。建议：CP-A为W01/W02的准备管线修复，获得正常CI反馈；CP-B为独立快照/桌面/文档组；CP-F为最终必要整合。只有需要新CI时才推送中间候选，不不断doc-only push取消尚在运行的同组CI。

中间检查点本地目标回归与必需审核须通过；跨平台待验收明确写WAIT_CI，不宣称阶段通过。总控自己读取可用GitHub结果；没有该能力时继续独立任务并在最终报告交由主会话集中核验，不安装gh或读取token突破限制。默认不手动rerun/cancelCI。

## 8. 交接与恢复

上下文不足、工具限额或执行中断时，立即把精确候选/任务状态/资源所有权保存到恢复记录，再退出；本地新总控读取这些记录接续，不用用户再转述全部历史。不得把“代理被中断”推断成没做过工作，也不重启尚在运行的同一push。

每个波次结束更新一次短摘要，不要求用户回复。只有阶段成果、不可替代的权限/环境决定或真正无进展时回主会话。执行器没有跨会话持续能力时，明确停止点和恢复命令，不能承诺后台自动完成。
