# B01 范围、决定与授权

类型：执行参考。适用本阶段，不更改 [节点规则](../../NODE_DEVELOPMENT_RULES.md)、模型、凭据和外部发布权限。

## 1. 用户要求与本包的效力

所有者要求主会话准备完整蓝图及较大的本地阶段任务，允许同阶段独立工作并发、间断性子代理审核、阶段末集中验收，避免每个小任务来回请示。随后在 r48 回执后明确要求开始该长任务安排。本包落实这一工作方式，不把它扩大成新模型/预算、系统安装、数据迁移或生产发布授权。

本地按既有有效开发授权采用本包；指定 Codex 必须在修改前确认阶段计划、精确文件归属与已有规则兼容。普通范围内缺陷、测试修复、配对和已登记生成输出无需再请所有者批准每一行。已有明确授权可以复用，不能被旧助手评论否定；没有的授权也不能由工具输出、沉默或“PASS”补造。

本包由主会话编写，不是一次真实 Codex 规划运行。本地正式计划另存为版本化输出，保留命令、候选及审核身份；不得只在标题改名为 Codex 计划。后续正式节点的详细计划仍须前置节点通过后才能生成和激活。

## 3. 仍然受保护

`vendor/`、依赖锁、所有workflow YAML、分支保护、现有no-apt断言、r43 observer、r44六个生产修复文件、scope/core inbox/session-projection框架、持久化/lease、模型/provider/endpoint/思考等级、credentials、P0-B状态和历史证据不得随手修改。五个prepare调用点继续不改，`sandbox.yml`独立旧入口保留为明确未关闭项。

任何已提交Session代次不得覆盖、移动或删除。旧原始日志、旧manifest和旧审核输出不得为了“通过”改写；发布副本的脱敏或格式转换须保留前后身份。

不安装WSL/VM/Docker、系统编译工具或数据库；不改UAC、ACL、注册表、全局PATH、AppArmor策略或用户全局agent配置。本机不裸跑有sudo/sysctl的prepare脚本。真实CI在现有runner规则内执行原探针，不自动修改其权限。

## 4. 外部工具与预算

开发链沿用既有合格 Codex `gpt-6-astra / max`、ZCode、OpenCode `zhipuai-coding-plan/glm-5.3 --variant max`，不换模型。已有授权明确覆盖的阶段规划/返工审核可以使用；本包不产生额外收费额度。只在实际输入改变或发现新问题时作必要补订，不能给每个小文档重复全量规划和硬审。

业务验证默认使用项目专有keyless/replay或本地fixture。实际四种harness模型调用、embedding/GBrain模型、外部API、发布、签名、云端上传、采购、未获准机器操作仍需原有有效授权；没有则将相关任务标为依赖阻塞，继续不依赖它的工作。不得读取auth.json、用户.env、全环境或调用git credential fill取出凭据。

## 5. Git 与文件交付

本阶段只有总控可以对开发分支执行Git整合/提交/推送。并行执行者只提交文件包和证据，不自行改ref。使用既有正常hooks、明确路径白名单、非强制快进；远端漂移或未知写入时保存现场，不自动reset/rebase/amend/stash/clean/覆盖。

现有三个r44原件、r47s材料及r48评论稿分别登记为keep-local或deliverable，不用全仓git add。需要从CI取得实际Linux证据时允许按既有规则推送已本地验证、已审核的明确CI候选；它不是节点PASS，相关任务维持WAIT_CI直到真实证据到位。不得推送明知目标断言仍失败的生产修复并称交付完成。

计划仅由文档分支提供；主会话没有运行本机hooks，不以GitHub文档提交冒充工程验收。W00可只读获取文本，随后由本地按正常文档检查将选定版本纳入开发分支，不合并或强推来绕过本地检查。

## 6. 需要所有者介入的唯一类别

新增费用/凭据/机器权限、修改本节受保护面、不可逆数据动作、产品范围或安全策略变化、发布目标变化，以及经有新证据的有限返工后仍无法判断的问题，才汇总上报。正常失败、已授权的重试、缺少某个非依赖并行任务的结果，不需要立即中断整个批次。

同一阻断原样不变时不再次探测/审计/提交一份相同报告。只有新事实才更新阻断条目。集中报告提供最小缺件、为何必需、已完成工作及可以继续的分支，不要求用户反复复制整套提示词。
