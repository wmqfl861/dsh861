## What the new script does (acceptance-relevant behavior)

Pins the three inputs (source, meson, libcap) with publisher-recorded digests; verifies each digest before unpack; audits member listings (absolute/traversal/tab names, device members, out-of-root symlink/hardlink targets, unparseable link lines, unterminated final lines) before extraction; extracts everything under `${RUNNER_TEMP}/dsh-bubblewrap-private/`; handles the deb as data via `dpkg-deb --field`/`--fsys-tarfile`/`--extract`; generates a private `libcap.pc` (the shipped one's `libdir=/usr/lib64` does not match the payload path — consuming it would silently fall back to host lookup) and restricts `PKG_CONFIG_LIBDIR` to it; removes the dangling `libcap.so`/`libpsx.so` dev symlinks so `-lcap` resolves only to the audited `libcap.a`; configures via `meson.py setup ... -Dprefer_static=true -Dtests=false -Dman=disabled -Dbash_completion=disabled -Dzsh_completion=disabled` (SELinux left at upstream default `auto`; under the restricted path Meson reports it not found — matching Ubuntu's AppArmor platform); compiles with `--verbose` and requires the captured link command to reference the private libcap directory; requires the ELF to be `elf64-x86-64`, `objdump -p` NEEDED and `ldd` to show no libcap, and `--version` to print exactly `bubblewrap 0.12.0`; records source/dependency/artifact SHA-256 lines separately; keeps the r47 sysctl line and failure semantics unchanged; runs the same functional probe; publishes `GITHUB_PATH` only after the probe passes. Preflight requires `curl sha256sum tar dpkg-deb python3 cc ninja pkg-config objdump ldd` on PATH and installs nothing.

## Independent-review remediation (conditional PASS; both fixes in the stub layer only)

The fresh-context review confirmed the trust chains, the `libcap.pc` libdir finding, the line-by-line script semantics, the zero-change proofs, and NOT_RUN honesty, and reproduced two nondeterministic failure mechanisms in the delivered spec's stubs. Both were fixed in `scripts/prepare-ci-bubblewrap.spec.ts`; `scripts/prepare-ci-bubblewrap.sh` and every trust-chain artifact are byte-identical through the remediation (script SHA-256 re-verified `28d31aa9…d53a3` before and after).

- Gap 1 (false green, ~3% of runs): the objdump stub dispatched on whole-argv substring patterns, so a random temp-dir name containing `-f` (e.g. `run-fXy9Z8`) routed `objdump -p <path>` into the `-f` branch and silently skipped the NEEDED output. Fix: exact-match dispatch on `$1` (`-f)`/`-p)`) plus a loud `*)` rejection for any other first argument. Deterministic check: `objdump -p` on a `run-fXy9Z8` path now emits the NEEDED line; `objdump -f` still emits the format line; an unexpected first argument exits 2.
- Gap 2 (false red, ~2.5–5% per deb pipeline): the tar stub's stdin branch replied without reading stdin, so under pipefail the upstream `dpkg-deb` stub could write into a closed pipe read end and fail the pipeline as a diagnostic-less "rejected unsafe member names/metadata". Fix: the stdin branch drains stdin to EOF (`cat > /dev/null`) before replaying its fixtures. Deterministic check: 200 writer→`tar -tf -` pipeline iterations, 0 failures.
