## nativeResume 与 artifactHandoff

`nativeResume` 是产品原生会话续接能力。没有原生接口时明确声明不支持，不拼接聊天记录或伪造 session id 冒充。

`artifactHandoff` 是平台的步骤级交接。第二个真实实例可以新建会话，验证稳定成员/项目/任务身份、输入版本、产物引用及摘要、适用授权和规则版本，以及下一步目标。要实际执行一次产物检查或后续工作，不能仅由模型口头确认“记住了”。这不要求迁移隐藏推理或原生 Session。

同一成员跨 harness 的 GBrain 记忆连续性仍由对应集成节点验证，不能用一个文件交接把完整 AC-04 标记通过。缺少 nativeResume 不得单独否决真实、获准的 artifactHandoff。

## 节点边界和准入

P0-B 保留四种真实 harness 的最小适配、配置发现、隔离、允许/拒绝、受控取消和可行交接验证。完整的公司身份平台、中央 skills/tools/MCP 控制面、PostgreSQL/GBrain 和工作流运行管理仍属于路线指定的后续实现。

真实工具连接的最小探针仍需验证；“完整中央控制面不在 P0-B”不是删除最小工具连接验收。四种产品的必需能力缺少证据时继续阻塞，不以文本响应、mock 或别名替代。

不得把后续完整控制面或所有产品的原生 continuation 无条件增加为 P0-C 的前置。修订者必须写出有限的 P0-B 必需项、可选项、后续项和各自退出条件，避免循环依赖；不允许把未实现的完整产品 AC 偷改为通过。

当前仍不允许进入 P0-C。解除准入需要真实 Codex 的后继计划、该范围实际完成的证据、固定候选，以及指定真实 OpenCode 对该候选的 PASS。本请求和离线门禁均不满足上述条件。

## 可观测性和权限

分别记录批准配置、实际提交配置、原生程序观测值和不可观测字段。必需指定配置无法落实时阻塞；非必需遥测缺失如实记 UNKNOWN，不伪造，也不要求所有接口返回同样的字段。Grok 的模型不一致保持未解决，禁止未经授权改成别名。

拒绝证据应区分产品原生权限、平台能力入口和操作系统执行边界；每个 case 必须记录真正的操作尝试、实际拒绝来源和无副作用检查。模型拒答和没有发生工具调用不能证明执行层限制。取消同样区分原生确认、进程终止和副作用核实，不用杀进程冒充原生确认。
