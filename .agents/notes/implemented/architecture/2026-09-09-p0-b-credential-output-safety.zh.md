# Agent Note：显式凭据租约与脱敏输出采集

Status: implemented

[English](2026-09-09-p0-b-credential-output-safety.md) | 中文

## 问题

P0-B 需要显式凭据来源和不泄漏秘密的证据。序列化带凭据的对象、转发原始诊断或独立检查每个传输块都可能泄漏值。子进程成功退出不能覆盖已经检测到的泄漏。

## 决定

`scripts/p0-b/` 的独立 B0 组件只解析已经明确授权的来源到目标映射。可信 reader 由调用者注入，不自动发现环境、文件或聊天记录。一次性 lease 默认仅暴露安全元数据，并在回调结束后释放自有引用。JavaScript 无法保证物理内存擦除，也无法撤销恶意回调保留的副本。

每个输出通道使用独立的增量 UTF-8 脱敏器，保留未决前缀并覆盖重叠匹配。支持已知原值、标准 JSON 转义、规范 URL/表单及 base64 表示，不承诺任意编码或未知秘密。调用者提供的大小边界经过校验。泄漏状态锁存，可以通知可信进程 owner，但不自行终止进程。

采集器在持久化前脱敏，遵守背压，以 POSIX 私有权限排他创建固定文件名，执行本次调用固定的输出限额，只计算脱敏字节的摘要。中断时丢弃未决原始后缀。运行根目录和父目录仍由可信 owner 负责；这些机制不等于操作系统沙箱或 Windows ACL 策略。

启动前逐个检查原始参数，避免二次 JSON 编码掩盖已转义凭据。输出 gate 区分证据缺失、泄漏与成功采集。已经检测到的泄漏返回 FAIL，即使另一通道缺失或格式错误也不受报告顺序影响；无效的同伴证据不能抹除泄漏事实。它绝不认证产品或节点 PASS。这些 helper 尚未接入现有 Codex provider 的原始 stderr 转发，也没有实现计划中的语法级来源扫描器。

## 考虑过的替代方案

对每个数据块单独正则替换会漏过跨块秘密。先保存原始字节再清理为时已晚。把退出零或成功采集当作产品验收混淆了独立事实。自动读取全局配置则违反显式来源边界。

## 影响

[历史验证记录](../../../../development/remediation/2026-09-09/security-r02/verification.json) 保留 focused 编译、合成子进程测试、首次失败的 argv 回归及修复。[源码回归](../../../../scripts/p0-b/__tests__/security.test.mjs) 还在 Windows 上验证了两种顺序下的无效同伴证据。真实产品接线、指定规划/审核和产品验收仍未完成，历史计划与回执保持不变。
