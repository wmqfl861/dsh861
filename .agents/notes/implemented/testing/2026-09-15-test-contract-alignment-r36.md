# Agent Note: Re-align five drifted test contracts after the toolchain upgrade

Status: implemented

English | [中文](2026-09-15-test-contract-alignment-r36.zh.md)

## Problem

The Node 26 / pnpm 12 / action-version upgrade and r35's config rework left five test contracts asserting superseded shapes, so both coverage lanes failed on contract drift instead of product behavior. The proxy-wiring spec in [test-proxy-environment.spec.ts](../../../../scripts/test-proxy-environment.spec.ts) discovered `setupFiles` slots with a regex that only matches array literals; after r35 moved the root config onto a shared `testSetupFiles` constant, `vitest.config.ts` was filtered out of discovery and its three slots (root, `thread-safe`, `process-bound`) escaped the per-slot check entirely — a dropped proxy setup there would pass silently. The preview-workflow spec still expected `PRIMARY_NODE_VERSION: '24'` while [build-preview-cloudflare.yml](../../../../.github/workflows/build-preview-cloudflare.yml) pins 26. The self-hosted CI specs still looked up `pnpm/action-setup@v4` and `actions/upload-artifact@v4`, both since moved to @v6/@v7 in the workflows; the @v4 lookup also compared an order against a `findIndex` result without first asserting the target step exists, so a rename degraded the check into a comparison against -1. The E2B subprocess spec discarded each `spawnTerminal` rejection with `void expect(...).rejects.toThrow(...)`, which Vitest 5 rejects as an un-awaited asynchronous assertion.

## Decision

Each contract now pins the current shape with its original strictness: the proxy-wiring spec resolves every `setupFiles:` slot to the array literal it names — an inline literal, or the initializer of a `const` identifier declared in the same file — and a reference with no array-literal declaration fails the spec instead of being skipped; the five-config discovery expectation, the per-slot containment check against `TEST_PROXY_SETUP_FILE`, and the root-config entry are unchanged. The preview spec expects Node 26; [release.yml](../../../../.github/workflows/release.yml) and [release-vendor.yml](../../../../.github/workflows/release-vendor.yml) keep Node 24 and their tests never asserted that value. The self-hosted CI specs pin `pnpm/action-setup@v6` and `actions/upload-artifact@v7` as exact strings (never prefix or any-version matching), keep every cache, isolation, retention, and command assertion, and the compatibility spec asserts the pnpm setup step exists (index ≥ 0) before comparing execution order with the cache-isolation step. The E2B graceMs case is `async` and awaits each `expect(...).rejects.toThrow(...)` individually, keeping the four illegal values, the synchronous `spawn` throw, and rejection before any remote work. No workflow file changed; no Node version was bulk-replaced.

## Alternatives considered

Weakening the proxy-wiring check to "the setup file name appears somewhere in the config" would pass while a single project disconnects; dropping the root config from the discovery expectation would have hidden the constant form again. Matching `pnpm/action-setup@` without a version would keep the order check alive but stop pinning the audited action version. Skipping the E2B test or wrapping the rejects chain in `vi.waitFor` would mask the discard instead of awaiting it.

## Consequences

Verified on Windows against the real toolchain (Node 26.8.2, pnpm 12.4.1): each file was first run to its genuine failure (proxy spec 1 failed — `vitest.config.ts` absent from discovery; preview 1 failed on `'24' ≠ '26'`; release spec 5 failed across the two version drifts; E2B 1 failed on Vitest 5's "rejects assertion was not awaited"; the compatibility spec passes locally with 2 Windows-skipped Bash tests, which do not count as Linux passes — its drift is proven by the workflow text). After the fixes all five files pass (8/8, 3/3, 4 passed + 2 skipped, 79/79, 70/70) and [vitest-project-inheritance.spec.ts](../../../../scripts/vitest-project-inheritance.spec.ts) stays green. Real negative controls with byte-verified restores: removing the proxy entry from the shared constant fails the per-slot check, renaming one slot to an undeclared constant fails with "no array-literal const declaration", one project listing its own setup without the proxy entry fails its own slot, and reintroducing the `void` discard fails on the un-awaited assertion again. Evidence and gate outputs: [windows-execution/FINDINGS.md](../../../../development/remediation/2026-09-15/coverage-test-contracts-r36/windows-execution/FINDINGS.md); typecheck, lint, duplication, and test:docs all pass. Full instrumented coverage and the Linux lanes did not run in this round.
