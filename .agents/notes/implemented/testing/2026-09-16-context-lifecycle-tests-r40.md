# Agent Note: Observe Cordis lifecycle through declared dependencies and direct listener probes

Status: implemented

English | [中文](2026-09-16-context-lifecycle-tests-r40.zh.md)

## Problem

The latest-stable upgrade's Cordis lifecycle (vendor `ReflectService`) changed two observation paths that four context/lifecycle specs still relied on. Undeclared service-property reads in a scoped context now throw `cannot get property "…" without inject`, and a declared-but-revoked dependency rejects with `cannot get required service "…" in inactive context`. Concretely: the session-fork spec read `child.ctx.systemPrompt` directly; the gateway spec's recovery path read `fixtureScope` — calling-context metadata the test never established — so the fixture's `?? 'root'` never executed; the goal spec expected the stale service instance's old projection error, but its revoked `agents` dependency rejects first; and the session-reference spec used the stale resolver's `prepare` succeeding as its only evidence that the assemble listener was gone, while pre-step listener removal had no observation at all ([r39 acceptance](2026-09-16-sdk-manifest-contracts-r39.md); CI [run 35057856906](https://github.com/wmqfl861/dsh861/actions/runs/35057856906)).

## Decision

Each spec now observes the same shipped behavior through a path the upgraded lifecycle admits, and every removal claim has its own positive control. The fork spec creates an injecting test plugin fiber under `child.ctx` (`child.ctx.inject(['systemPrompt'], …)`) that calls the real `systemPrompt.assemble(assembleContextFor(child))` in the child's own assembly scope, asserts the observer executed exactly once and produced the assembly, and keeps the inherited provider/model/reasoningEffort assertions and the real `agent/request` waterfall unchanged. The gateway spec's recovery invocation goes through `ctx.extend({ fixtureScope: undefined })`: the fallback case is calling-context metadata established explicitly (value undefined), the result asserts `scope: 'root'`, and no production gateway dependency changes. The goal spec pins the stale instance's rejection to Cordis's exact layered message `cannot get required service "agents" in inactive context` while keeping the live-root service and projection removal, the reinstalled-instance identity check, and the disarmed restore. The session-reference spec proves both listeners directly: a counting probe registered inner to the resolver's prepend listener observes the real assemble callback reading the assembly's route variables exactly twice per execution before disposal and zero after; the real pre-step dispatch passes the seed decision through by object identity with no reference-source read after disposal; the stale `prepare` rejection (`SESSION_REFERENCE_READ_FAILED` with the inactive-`sessionQuery` cause) is a separate assertion; and reinstalling the resolver restores exactly one copy of each callback (two route reads, one appended context message). The test disposes its probe, spy, and reinstalled fiber in `finally`.

## Alternatives considered

**Reading `systemPrompt` from the root context or via `ctx.get(name, false)`.** Both bypass the child-scope injection contract the failure exposed; `get(false)` answers any caller regardless of scope, so the observation would no longer exercise the child's assembly scope at all.

**Registering `fixtureScope` as a service or adding an `inject` to the gateway.** `fixtureScope` is test-owned calling-context metadata carried by `ctx.extend`, not a production dependency; a gateway change to satisfy a fixture would alter shipped composition for the other scope assertions.

**Accepting any thrown error for the stale goal and resolver instances.** A bare `toThrow` passes when any layer rejects, including an unrelated one; both rejections are now matched against the exact dependency-layer message so a future bypass shows up as a different failure.

**Keeping the stale `prepare` call as the listener-removal proof.** It observes the revoked `sessionQuery` dependency, not listener registration state; under a leaked registration the observation no longer discriminates. Removal evidence (assemble probe, pre-step passthrough) and staleness evidence (dependency rejection) are separate assertions.

## Consequences

The unfixed four-file baseline failed exactly 4 of 135 tests, matching the CI first failures. The fixed run passes 135/135, and each removal claim is anchored by a live positive control in the same test (observer executed once, real mention processed, context appended). Two independent leak negative controls — temporarily registering exactly one of the resolver's two listeners on the root context in `packages/context/session-reference/src/index.ts` at a time — each failed only the targeted assertion (the destroyed assemble callback still read the route variables, 2 vs 0; the destroyed pre-step callback still executed and rejected through the revoked resolver instead of passing the seed through) while the other 46 tests passed; each mutation was restored byte-identically and verified by length, SHA-256, and git blob before a post-restore positive run of 135/135. Runtime implementation, vendor sources, the lockfile, and the r29–r39 evidence keep their bytes. This closes only the four context tests: the client hook, pwsh, FileHandle, coverage-threshold, and historical worker/Web failures from run 35057856906 remain out of scope.
