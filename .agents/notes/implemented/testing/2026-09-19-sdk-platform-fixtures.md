# Agent Note: Platform-resolved SDK snapshot sidecars, Windows hydration, and the pi-ai idle-budget guard

Status: implemented

English | [中文](2026-09-19-sdk-platform-fixtures.zh.md)

## Problem

The shared automatic SDK snapshot lanes (`snapshots/sdk/sdk.snapshot.ts`) compared both teardown scenarios against one set of platform-neutral expectations, and three independent facts made that impossible on Windows and incomplete on Linux. First, `hydrateReplayFixtures` replaced the `{{cwd}}` token in JSONL text with the raw `cwd` string, so any backslash separator produced illegal JSON escapes and `llm-replay` failed at plugin load (`Bad escaped character in JSON at position 87`); the dedicated teardown adapter already used the correct JSON-escaped spelling. Second, the parent tool schemas and system prompts are platform-flavored — win32 composes `pwsh` with the Windows-kill exit-code section (plus the Agent-Teams guidance for the team scenario), while the shared `session/text-turn` class pin carries the bash composition — so the shared sources cannot pass on win32. Third, the committed child sidecars were captured on win32, so the Linux child comparisons fail against pwsh bytes; conversely the agent-team parent is composition-specific on every platform (six team tools plus team-scoped redefinitions), which run 42 proved on Linux. Separately, the diagnostic expected suite tokenizes `{{cwd}}` through single-backslash spellings only, so the win32 sandbox policy text — which embeds the workspace root JSON-doubled — never matched the POSIX-recorded golden. Finally, the headless pi-ai expected case counted a fixed 2 requests while CI scheduling starvation could stretch title-request dispatch past the fixture's 1000ms stream-idle budget, emitting retries that fail the count on Linux CI and, through fail-fast, skipping the snapshot gate that the Linux sidecar evidence needed.

## Decision

Hydration now uses `JSON.stringify(cwd).slice(1, -1)` — the same spelling the dedicated adapter uses — writing hydrated bytes only to the run's temp fixture files. Expectation selection became platform-resolved through explicit registries in `sdk.snapshot.ts`: win32 resolves parent schemas, parent prompts, and child schemas from `.win32` sidecars; non-win32 resolves agent-team parent schemas and prompts and both scenarios' child schemas and prompts from `.default` sidecars; unregistered scenarios and unselected slots keep the shared sources. A selected-but-missing file fails loud through `readFile` — there is no cross-platform fallback, name-only substitution, or field filtering at comparison time, and the record/refresh write path uses the same selectors so a future refresh cannot clobber the wrong platform's bytes. Every sidecar derives from real keyless runs: the win32 schemas came from a `DSH_TEARDOWN_DUMP` capture extracted with the lane's own formatter; the Linux defaults were rebuilt from run 42's unified-diff hunks with every anchor, context, and deletion line verified line-exact against a reconstructed expected side, and the derived subagent child prompt is byte-identical to the shared source — the composition's own prediction. The diagnostic expected test passes `cwdAliases: [JSON.stringify(cwd).slice(1, -1)]` — the public `NormalizeContext` field — so the doubled spelling tokenizes without touching the normalizer; on POSIX the alias dedupes to a no-op. The pi-ai fix raises the fixture's `streamIdleTimeoutMs` from 1000 to 20000 (about three times the measured unstretched dispatch-lag lower bound, still inside the 30s subprocess diagnostic ceiling so a dead stream still fails loud) and adds an r29-style in-test guard asserting the budget is at least 10s; the 2-request contract and every existing assertion stay byte-unchanged.

## Alternatives considered

**Switch the production patch layer to bash on Windows.** The bundle's platform shell choice is production configuration, frozen for this change; the platform difference belongs in expectations, not in the shipped composition.

**Substitute tool names or filter fields at comparison time.** Both weaken the comparison; the full deep-equal against complete captured schemas is the contract being verified.

**Hand-write the win32 schemas from the bash sources.** Rejected without inspection; only bytes produced by real runs through the lane's own formatter were accepted, with structural diffs as review evidence.

**Loosen the normalizer to accept doubled-backslash spellings.** The golden comparison's token set is public API at the call site; the alias is the intended extension point and keeps the normalizer untouched.

**Mask the pi-ai retry count or raise the assertion.** The count is the scenario's contract; the budget that manufactures phantom requests under starvation is the fixture's own knob, and the guard makes any future regression to 1000ms fail deterministically in 5ms.

## Consequences

Twelve new sidecar files cover the full matrix (4 win32 schemas, 2 win32 prompts, 6 Linux defaults), and the win32 shared lane passes 2/2 — whole-session compare, parent schemas, and parent prompts — including under a space-plus-Unicode temp root and after negative-control restores; the expected dual-target passes 2/2 and the dedicated adapter 2/2 with the r46 delivery fence intact. Identity selection stayed at 15/15. Run 42's two Linux mismatches are now exactly the comparisons these sidecars serve, and the CI snapshot gate after the batch push is the authority for the derived Linux bytes. The pi-ai case passes locally at both old and new bytes and the negative control (old fixture under the new test) fails in 5ms on the guard; the CI `test:expected` gate remains the final judge for the starvation regime, which local Windows could not reproduce without instrumentation. No production package, normalizer, golden, replay input, or lockfile changed.
