# Agent Note: 静态文档全集的测试粒度

Status: implemented

[English](2026-09-08-static-document-corpus-test-granularity.md) | 中文

## 问题

两个覆盖全部 README 的测试各自将整批文件的发现、读取、解析和断言计入一个用例。随着文档数量增长，本可独立执行的文档检查共同占用同一个默认五秒测试预算。

P0-A 的失败记录表明，并发执行文档检查时两个用例均受影响，即使单独运行该测试文件，元数据用例仍然失败。这些观察确定了全量文档工作量与单例预算不匹配，但不能分别确定文件发现、读取、解析或断言的耗时。

站点检查暴露了相同的成本归属问题：完整 manifest（元数据清单）输出集中于一个准备钩子，导入构建辅助函数也会加载 VitePress 运行时。片段校验为每页创建 DOM 环境，但后续只需要属性值。记录保留这些单独运行时的失败事实，不对未测量的各操作耗时比例作推断。

## 决定

[P0-A v6 计划](../../../../development/nodes/P0-A/plan.v6.md) 采用单个 README 作为校验单位。[`scripts/doc-standard.spec.ts`](../../../../scripts/doc-standard.spec.ts) 只发现一次路径，并且仅共享路径数组；用例收集阶段不读取、解析或校验 README 内容。

六个文件发现 glob、排除项、路径规范化和排序保持不变。元数据检查覆盖发现的每个 README；正文结构检查保留原来路径包含四个部分的过滤条件。英文、中文、实验包、库和 bundle 的 README 仍按这些既有条件纳入检查。

每个参数化用例在测试内部读取并校验对应文档，使用原有辅助函数和全部既有断言。文件清单的非空断言仍然保留。各用例保留当前环境默认的 5,000 ms 预算，不新增用例、测试组或钩子的超时覆盖设置；用例名称标明所检查的路径。

小型纯内存用例通过现有错误收集函数检查无效 description、完整标题和缺失标题。必需的真实文件负向对照覆盖文件发现、读取和参数化登记；其证据必须显示指定的内容断言失败以及逐字节恢复，超时或用例收集失败不能代替这些结果。

[v7 扩展](../../../../development/nodes/P0-A/plan.v7.md)将逐文件执行应用于真实站点清单。单个投影迭代器在全部规范页面和 index 别名之间保留路由和图片占用记录；同步发布完整耗尽同一个迭代器。顺序执行的共享输出测试组先输出所有文件，再逐文件检查整棵目录树中的链接。原有清单、首页和全树链接断言仍然保留。

Git 仅发现一次 NUL 分隔的路径，不在收集阶段将其判为合法。VitePress 只在实际构建时加载。片段校验每次调用使用一个完整文档 DOMParser 环境，把 id 和 href 复制到普通数据后关闭环境；解析禁用脚本，并保留文档级元素、旧式锚点、重复引用和 URL 规则。

测量表明，HTMLCollection 迭代会反复对 `length` 执行名称查找，并在每一步扫描全部元素；在 9,216 个元素上推进 100 步的探针产生 921,600 次候选扫描和 1,056 ms 的遍历耗时。静态 `querySelectorAll('*')` NodeList 的索引访问避免了该迭代器成本，同时保留完整文档解析、文档顺序以及现有的 id、`a[name]` 和 `a[href]` 语义。验收不以任何时间阈值为条件。

逐文件执行仍承担完整的 GFM 解析成本。四个完整的配置和工具 catalog 路由使用明确的 15 秒局部集成预算；该预算不构成性能保证。

## 考虑过的替代方案

**提高超时。** 更大的额度仍将不断增长的全量文档工作计入一个用例，只会推迟同类失败。它不能修正这些独立文档规则的校验单位。

**反复运行相同代码直到通过。** 挑选一次有利的运行结果既不改变工作量，也会掩盖原始失败。仅凭后续一次通过，不能确定测试组织方式可靠。

**串行执行全部文档检查。** 消除资源争用会改变正常执行条件，也不能解释单独运行时观察到的元数据失败。仓库的并发验证仍是相关执行环境。

**缓存文档内容、已解析元数据或 manifest（元数据清单）。** 这些缓存增加了状态和失效管理职责，却没有解决全量文档共用单例预算的问题。将读取或校验移到用例收集阶段也会使这些工作离开单个测试；共享数据仅限于发现的路径。

## 影响

更多测试用例使失败能够定位到单个 README 路径。文件发现和总执行时间仍取决于文件系统性能，完整扫描可以超过五秒；本决定没有为全部文档设置五秒上限。[测试政策](../../../../docs/testing.zh.md) 继续约束测试执行及其证据。

覆盖证据要求修改前后的完整有序文件清单精确相等，并与实际 Vitest JSON 报告中两组参数化用例经排序后的路径精确比较。每个预期用例都必须通过，不得缺失、多出、跳过、标为 todo 或重复登记；仅比较数量或集合不能确定覆盖完整。

站点覆盖还须保留每个原始用例身份，检查实际输出的每个清单路由和别名，并验证冲突、解析及部分输出场景。其负向对照添加一个未被忽略的站点文档和自有输出树中的坏链接，然后核实准确失败和清理。迭代器创建与逐文件测试不会消除全部投影成本；提前停止会留下由调用者负责清理的部分输出。

本 Agent Note 记录测试决定的采用。命令记录负责具体尝试、耗时、恢复证据和验证结果；审核回执负责节点验收。本 Agent Note 不声称修复、文档检查或必需的独立审核已经通过。
