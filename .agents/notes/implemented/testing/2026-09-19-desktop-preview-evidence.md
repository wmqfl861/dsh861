# Agent Note: Desktop preview fixtures and the fs-ext migration cleanup behind artifact packaging

Status: implemented

English | [中文](2026-09-19-desktop-preview-evidence.zh.md)

## Problem

The Desktop app had no keyless, test-owned way to boot a real Electron window with a model fixture, and artifact-mode packaging on Windows failed unconditionally for a reason unrelated to signing: the flock migration (`d927cbff99`) replaced the only `fs-ext` dependency (`packages/session/session-persistence-jsonl`) with `@deepseek-ai/node-addon-system`, after which no package in the repository declares `fs-ext` — yet `apps/desktop/tests/fixtures/runtime-payload-smoke.mjs` still called `checkFsExt()` unconditionally, so `prepare:dsh`'s smoke step deleted the assembled target and every signed or unsigned Windows package failed at that step. Two smaller blockers compounded it: pinned pnpm 12.4.1 ships no `main`/`exports`, so `prepare-runtime.ts`'s `require.resolve('pnpm')` could not resolve; and the first preview-fixture attempt injected its patch layer into `apps/desktop/.desktop-build/development/project/` — the user-visible development project — where the real owner client then failed to start (the fixture imported bare `@deepseek-ai/*` names unresolvable from the project context).

## Decision

Three pre-registered fixtures under `apps/desktop/tests/fixtures/` now own the preview path: `b01-preview-model.mjs` (a keyless mock adapter with zero bare-package imports), `b01-preview.cordis.patch.yml` (a patch layer guarded by `DSH_B01_PREVIEW` so it activates only in test boots), and `b01-preview-launch.mjs` (a launcher that assembles the test profile into a test-owned app directory, with an ownership assertion refusing paths outside the test root and the repository development directory, backup-before-assembly, and restore on exit). The rework conditions from the incident are structural: the fixture must not import bare workspace names from a project context, and assembly is scoped to a home the real client never reads. The fs-ext cleanup removed all four remnants as dead code, each evidenced against the migration history: the exclusion rules in `runtime-file-policy.ts`, the `fs-ext: true` allowBuilds entry in `project-manager.ts`'s generated workspace file, and the smoke check itself. The smoke now verifies the successor surface instead: `checkSystemFlockGate` resolves the `node-addon-system/flock` entry inside the packaged runtime and asserts the documented win32 platform gate (`ERR_FLOCK_UNSUPPORTED_PLATFORM`) — win32 session locking goes through koffi, which the existing `checkKoffi` already covers. The spec's fs-ext-specific fixtures became a neutral native-sample pair proving the same generic retention semantics plus a node-pty out-of-container assertion. `prepare-runtime.ts` resolves `pnpm/package.json` by subpath, restoring the resolve-to-manifest contract without depending on pnpm's `main`. The remaining Windows build blockers were solved at the call layer only — an absolute-bash invocation with the workspace-pinned pnpm wrapper as `npm_execpath`, a PATH shim selecting bsdtar over GNU tar for `C:`-prefixed paths, and an `fd-slicer` stream shim injected via `NODE_OPTIONS` into the build process tree only — with no repository bytes changed.

## Alternatives considered

**Restore the `fs-ext` dependency.** Runs against the flock migration's direction; the closure provably no longer contains the package, so the declaration would be dead weight the smoke then re-demands.

**Keep the smoke asserting fs-ext behind a platform guard.** The module cannot be required at all on any platform after the migration; a guarded skip would leave the successor surface unverified.

**Assemble the test patch into the development project before rebuild.** The project is rebuilt by every dev/start run and is user-visible; injection there is both unstable and outside test ownership — the recorded incident.

**Install the missing system tools (NSIS, GNU tar replacement, new pnpm).** Out of authorization for this batch; each was either worked around at the call layer or reported as a precise blocker.

## Consequences

The five target Desktop specs pass 25/25 and the packaging-adjacent spec set 39/39 at final bytes, with a negative control proving the removed fs-ext assertion is still enforced (restoring one old assertion fails exactly one test). The unsigned runnable directory builds through the full chain — `build:official`, three release tarballs, host pack, runtime/package-set/dsh preparation, electron-builder terminal step — producing a 980 MB `win-unpacked` (11,747 files, per-file manifest with SHA-256), and the seven-action journey replays on the artifact from the built directory, not a dev server, with per-run process-tree, `/json/version`, and CDP identity captures, single-instance behavior, and 241/241 profile junctions verified with the target directory preserved. The local security policy that denies junction and DLL-named writes to unsigned process chains is documented in the product README as an environment fact, with the bootstrap workaround byte-equivalent to the product's own `applyRelease` fast path. NSIS remains absent and unauthorized, so the installer is not built; signing and publishing are untouched unsigned-path behaviors (`publish: never`, no auto-update).
