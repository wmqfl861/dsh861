# Agent Note: Bound the gate runner descendant walk and stop late-close re-walks

Status: implemented

English | [中文](2026-09-15-gate-descendants-traversal-r37.zh.md)

## Problem

The Windows coverage runner crashed (run 34981717505, job 104423422677) with `RangeError: Maximum call stack size exceeded` inside `collectDescendants` in [run-gates.ts](../../../../scripts/run-gates.ts): the breadth-first queue aliased the root's own child list and grew it with `queue.push(...children)`, so a dequeued pid with a wide child list exceeded the function-argument limit, and with no visited set a cycle could re-enqueue pids forever — once the cycle led back to the root, the queue reached itself and spread itself onto itself. Repeated rows also duplicated descendants. Separately, the asynchronous enumeration's close handler evaluated `collectDescendants(root, parsePidPpidLines(stdout))` before calling `finish`, so after cancel or error settled the promise, a late close still re-parsed and re-walked the whole captured table synchronously. No original CIM rows were captured, so the defects are reproduced on constructed tables, not on a historical pid graph.

## Decision

`collectDescendants` keeps the adjacency build, then runs a deduplicated iterative breadth-first walk from its own `[root]` queue with a `seen` set pre-seeded with the root: each reachable pid is enqueued and emitted exactly once at first discovery, the root itself is never returned, cycles and repeated rows are skipped rather than aborting the walk, and children are enqueued one at a time — no spread, no recursion, no depth or size cap. The asynchronous wiring is extracted as `wireDescendantEnumeration` with identical stdout accumulation, one-shot settle, enumeration-child termination on settle, and cancel/error semantics; the settled check moved to the top of the close handler, so a late close returns before touching the captured output while `finish` keeps its own one-shot guard. Sampling cadence, cache merging, fail-fast and abort distinction, exit-code and signal reporting, output draining, termination deadlines, and the Windows taskkill root-first semantics are unchanged.

## Alternatives considered

A depth cap or maximum-descendant bound would truncate real gate trees exactly when they are widest. Returning an empty list upon detecting a cycle would drop the root's other descendants. Recursion would trade the argument limit for a stack limit. Keeping only `finish`'s internal guard was rejected with evidence: its check runs after the argument expression is evaluated, and the probe below shows the re-walk still executes.

## Consequences

[run-gates.spec.ts](../../../../scripts/run-gates.spec.ts) gained regressions for the empty table, multi-level breadth-first order, a root with no row of its own, repeated rows, a pid reachable on multiple paths, unchanged input rows, a 200000-wide root and non-root child list, a 100000-deep chain, a self-loop, a cycle back to the root, an unrelated cycle, a branch that cycles back while others stay acyclic, and seeded random tables cross-checked against an independent per-pid parent-chain reachability computation. Inputs that an unbounded walker would never finish walk inside a short-lived tsx child stopped by the test's own `spawnSync` timeout, so a regression cannot block the forked worker. The asynchronous wiring is checked for normal close, chunked stdout, error then late close, and cancel then late or repeated close, pinning settle and kill counts. The genuine first failure against the repository implementation was recorded (8 failed, including the same `RangeError` as the CI crash); negative controls with byte-verified restores: removing visited fails the 6 cycle and dedup tests, restoring aliasing plus spread fails 7 by adding the wide-list `RangeError`, and restoring eager close with the fixed walker re-walks a 2000000-row table for 2631 ms inside a late close where the guard takes 0 ms. Verified on Windows (Node 26.8.2, pnpm 12.4.1): both suites 130 passed with 6 pre-existing Windows skips, typecheck, lint, and duplication pass. Evidence: [windows-execution/FINDINGS.md](../../../../development/remediation/2026-09-15/gate-descendants-r37/windows-execution/FINDINGS.md). The Linux coverage failures, the session.lock FileHandle exceptions, the 64-file coverage shortfall, and the Windows adapter idle-watchdog failure remain untouched; the marginal abort test that exceeds its 5-second budget when a loaded host slows the synchronous CIM enumeration is pre-existing and unchanged.
